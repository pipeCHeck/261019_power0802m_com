# Ball Game Implementation Plan

**Goal:** Add a minimal ball keep-up game to the existing page. The follow-up appearance uses a filled 36px ball that inverts its backdrop.

**Spec:** `docs/superpowers/specs/2026-10-19-ball-game-design.md`

**Architecture:** A dependency-free physics module owns the ball and score. A browser module renders a pointer-transparent canvas and a small score ticker, keeping the existing page intact.

## Constraints

No external packages, game menu, modal, navigation, background panel or bold graphics. Ball motion must use elapsed time. Scores start at zero. Pointer coordinates remain in CSS pixels independently of canvas pixel density. Reduced motion suppresses decorative effects. Timers from a lost game must never hide a new game's score.

- Browser checks cover first0, falling hits, both horizontal directions, misses, score10/fireworks, GG slide and exit, restart during GG, score edge clamping, resizing, touch, reduced motion and existing links.
